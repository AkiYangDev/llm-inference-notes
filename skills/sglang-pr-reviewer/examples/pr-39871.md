## Problem

Expected：`tp_size=16, dp_size=2, cp=1, DPA=on` 时 `attn_tp_size=8`。Actual：旧日志打印 `attn_tp_size=16`。

## Invariant

所有描述 Attention TP 宽度的消费者，应和 Runtime rank/group 派生共享同一 Attention width 语义。

## Failure Path

`derive_attention_widths()` 已得到 8，但旧 Logging 旁路 helper，直接消费 `cfg.tp_size=16`。

## Why this fix

正确修复不是另写 `tp_size // dp_size`，而是复用 `derive_attention_widths()`：真实规则还包含 `enable_dp_attention` 和 `attn_cp_size`，并且 helper 本身就是 rank computation 的共享 arithmetic。

## Evidence

- Source-confirmed：merge commit 的 `runtime_context.py` 与 `model_hook.py`。
- PR-confirmed：作者明确说明 log-only、no behavioral impact。
- Measured：无性能/精度 benchmark；不需要虚构。
- Transfer：Configured Value vs Derived Runtime Value 是可迁移 Bug Pattern。

## Scope

该日志分支位于 CUDA / ROCm DSA model-specific adjustment；不能写成 Ascend 910C runtime fix。

## Review Rule

看到 `cfg.xxx` 被运行时消费者直接使用时，检查是否存在对应的 derived runtime value 或统一 helper。
