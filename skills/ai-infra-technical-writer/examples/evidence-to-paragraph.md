# 从证据到可读段落

这是人工构造的教学示例，展示规则如何改变表达，不是受控的有无 Skill 对照实验。所有 token 符号都是代号，不对应具体分词器。

## 输入任务与材料

任务：面向后端工程师，解释普通自回归生成中首 token 与后续 Decode 的关系。

本例约定：单条请求、三枚 prompt token A/B/C；无前缀复用、无 chunked prefill、无投机推理；只讨论逻辑状态，不映射任何特定 DeepSeek 版本或物理缓存布局。

| 证据 ID | 类型 | 本例给定条件 |
|---|---|---|
| E1 | 教学假设 | Prefill 处理 A/B/C，由最后位置的 logits 采样得到 y1 |
| E2 | 教学假设 | 下一轮以 y1 为新增输入，处理后采样得到 y2 |
| E3 | 范围限制 | 未提供框架源码、设备 trace 或性能测量 |

待修正的文字：

> Prefill 生成所有 token 的 KV，Decode 从缓存里取出答案。每轮调用 NPU kernel 后立即返回一个汉字，所以缓存命中后不需要计算。

## 参考输出

模型先处理输入序列 A、B、C，建立这些已处理位置的缓存，并根据最后位置的 logits 采样出首枚输出 y1。这里的 logits 是模型对候选下一 token 给出的分数；采样负责从这些分数中选出结果。

如果请求还没有结束，下一轮把 y1 作为新的模型输入。模型结合已有缓存计算它的表示，再采样出 y2。缓存复用减少了对历史输入的重复计算，后续生成仍然需要新的模型计算；答案并不是直接存放在 KV Cache 里。

| 轮次 | 本轮新增输入 | 本轮已处理的逻辑位置 | 采样结果 |
|---|---|---|---|
| Prefill | A/B/C | 0～2 | y1 |
| 第一次 Decode | y1 | 0～3 | y2 |

刚采样出的 y1 要到下一轮被处理时，才形成它对应的缓存状态。这张表描述的是普通自回归教学时序，不能直接当作某代 DeepSeek 的物理缓存布局。设备调用是否等待完成、输出如何被缓冲和返回，需要依据具体实现说明；一枚 token 也不必然对应一个汉字或一条流式消息。

## 为什么这样改

保留输入、计算和采样的时间关系，删除“缓存里取答案”的错误因果；用同一请求解释状态推进；对没有材料支持的 NPU 调用和返回行为停止断言。本例不提供函数名或性能数字，因为输入没有对应证据。
